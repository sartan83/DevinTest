# FileAgent

A **local-first AI file organization agent for Windows**. FileAgent scans the
folders you allow it to touch (Downloads, Documents, Pictures, …), classifies
every file, proposes a concrete organization plan, and applies only the changes
you approve — with a full audit trail and one-click rollback.

The agent runs entirely on your machine. No network access is required for the
core feature set; any optional AI provider is off by default.

![architecture](docs/architecture.svg)

## Principles

- **Local-first.** Scanner, classifier, planner, executor, database — all on your PC.
- **Safe by default.** Root allowlist, system-path deny-list, no permanent deletes.
- **Human-reviewable.** Every proposed action shows `before`, `after`, rule, reason, confidence.
- **Reversible.** Every applied action writes a rollback token; the Undo tab reverses them.
- **Modular.** Backend modules map 1:1 to the `backend/fileagent/` layout.
- **Deterministic first, AI second.** Rules are enough for the MVP; AI is a pluggable enhancement.

## Architecture

```
┌────────────────────────────┐   HTTP (loopback + bearer token)   ┌───────────────────────────┐
│  Electron + React (UI)     │ ─────────────────────────────────► │  Python FastAPI sidecar   │
│  src/, electron/           │                                    │  backend/fileagent/       │
└────────────────────────────┘                                    │                           │
                                                                  │  scanner → classifier →   │
                                                                  │  rules_engine → planner → │
                                                                  │  executor → audit →       │
                                                                  │  rollback                 │
                                                                  │                           │
                                                                  │  SQLite: %APPDATA%\\      │
                                                                  │          FileAgent\\agent.db│
                                                                  └───────────────────────────┘
```

**Why this stack (briefly):** Electron + React gives a polished Windows-native
multi-page desktop UI with very little bespoke code. The heavy lifting — file
walks, hashing, PDF/DOCX text extraction, future ML — is delegated to a Python
sidecar spawned by the main process on loopback (`127.0.0.1:53117`) with a
per-session bearer token. SQLite keeps the data layer trivial and portable. The
alternative considered was PySide6 (pure Python) — simpler single-language
build, but a worse UI story for a multi-page dashboard with live review tables.

### Backend modules

| Module                 | Responsibility |
| ---------------------- | -------------- |
| `scanner.py`           | Walk allowlisted folders, upsert `files_index` (optional SHA-256). |
| `content_extractor.py` | Bounded, best-effort text from PDF / DOCX / txt. |
| `classifier.py`        | Deterministic category + topic + confidence per file. |
| `rules_engine.py`      | 10 configurable default rules, each returning `Candidate` actions. |
| `planner.py`           | Runs rules, enforces safety, resolves conflicts, detects duplicates, persists proposals. |
| `executor.py`          | Applies approved proposals, re-checks safety, writes `executed_actions`. |
| `rollback.py`          | Reverses executed actions with safety re-check; records `rollback_history`. |
| `audit.py`             | Read helpers for the UI's Activity log. |
| `scheduler.py`         | Lightweight in-process scheduler + helper for Windows Task Scheduler. |
| `safety.py`            | Root allowlist, system-path deny-list, protected-extension guard. |
| `ai_provider.py`       | Optional AI hook (`NullProvider` default; `OpenAIProvider` sketch). |
| `api.py`               | FastAPI app: `/api/folders`, `/api/scan`, `/api/rules`, `/api/plan`, `/api/apply`, `/api/rollback`, `/api/activity`, `/api/settings`, `/api/batches`. |

### Data model (SQLite, see `backend/fileagent/schema.sql`)

- `watched_folders` — user-approved roots (+ role: downloads / documents / pictures / user).
- `files_index` — per-file metadata and optional hash.
- `classification_results` — history of category + topic + confidence per file.
- `organization_rules` — user-editable rule knobs (`enabled`, `mode`, `min_confidence`).
- `proposed_actions` — generated by the planner; status: pending / approved / rejected / executed.
- `executed_actions` — what actually ran, including `rollback_token` and `reversible` flag.
- `rollback_history` — every undo/redo attempt and outcome.
- `app_settings`, `scheduled_jobs` — global knobs and scheduler configuration.

## Default organization logics (MVP)

All 10 rules live in `rules_engine.REGISTRY` and are seeded into
`organization_rules` on first launch. You can disable any of them from the UI.

1. **Downloads → Installers & Archives** — `.exe .msi .zip .rar .7z .iso` etc.
2. **Screenshots → Pictures/Screenshots/YYYY-MM** — `Screenshot*`, `Cattura*`, `Capture*`.
3. **Finance** — PDFs with `invoice / fattura / receipt / order / ricevuta / bolletta` → `Documents/Finance/YYYY`.
4. **Career** — `cv / resume / curriculum` → `Documents/Career`.
5. **Contracts** — `contract / nda / agreement / contratto` → `Documents/Contracts` (approval required).
6. **Identity (sensitive)** — `passport / ID / codice fiscale / patente` → `Documents/Personal/ID` (approval required, never auto).
7. **Manuals** — `manual / handbook / guida / istruzioni` → `Documents/Manuals`.
8. **Downloads: group by type** — fallback bucket for PDFs / Images / Videos / Spreadsheets.
9. **Downloads: old temp files** — `.tmp .part .crdownload` older than 7 days → `Downloads/Review`.
10. **Archive old files** — anything older than N days (default 180) → `Archive/YYYY-MM` (approval required).

Duplicate detection (exact SHA-256) runs in the planner itself: any duplicate
set under a watched Downloads root becomes a `Duplicates_Review` quarantine
proposal — the oldest copy is kept untouched.

## Security model

1. **Root allowlist.** Every op must have both `before_path` and `after_path`
   resolve inside a row of `watched_folders`. Anything outside is silently
   dropped at plan time and hard-rejected at exec time.
2. **System-path deny-list.** `C:\Windows`, `C:\Program Files*`, `C:\ProgramData`,
   `AppData\Local\Microsoft`, `System32`, `SysWOW64`, plus the standard POSIX
   system roots (`/bin`, `/etc`, …) are hard-denied regardless of allowlist.
3. **Protected extensions.** `.sys .dll .drv .ini .lnk .msc .cpl` are refused by
   default. Requires explicit override flag to touch.
4. **No permanent deletes.** "Delete" always means move to a quarantine folder
   under the source root.
5. **Dry-run first.** `Analyze` and `Preview` never touch the disk. Planning
   always precedes execution, and proposals are persisted so a user can audit
   them before approving.
6. **Approval gates.** Every rule has a `risk` tier: `safe`, `review`,
   `sensitive`. The Rules tab enforces that `sensitive` can never run in `auto`
   mode. Actions below a per-rule `min_confidence` threshold always require
   approval, even in auto mode.
7. **Confidence threshold.** Global floor configurable in Settings.
8. **No network.** AI provider defaults to `NullProvider`. Any outbound HTTP is
   gated by a single `allow_ai` setting.
9. **Full audit.** `executed_actions` records before/after path, op type, rule,
   success, error, `reversible` flag, and `rollback_token` for every attempt.
10. **Loopback-only sidecar.** The Python API binds to `127.0.0.1` and requires
    a bearer token generated fresh by Electron on every launch.

## Rollback

- Every `apply` invocation is grouped into a **batch** (UUID). The Undo tab
  lists all batches, newest first.
- Undoing a batch walks its `executed_actions` in reverse and tries to move
  each `after_path` back to `before_path`. Safety is re-checked on the reverse
  op.
- Each undo attempt writes a row to `rollback_history` (success or failure +
  error message) so the audit trail is complete.
- Successful undo sets `reversible = 0` on the original row to prevent
  double-undo.
- If the original path is now occupied (user changed their mind), undo refuses
  with a clear error — no silent overwrites.
- Quarantined / archived files are reversible the same way (the quarantine is
  just a folder under the source root).

## Setup (Windows — local dev)

```powershell
# Prereqs: Python >=3.11, Node >=20, git.

git clone https://github.com/sartan83/DevinTest.git
cd DevinTest\file-agent

# 1. Python sidecar
py -3.11 -m venv backend\.venv
.\backend\.venv\Scripts\Activate.ps1
pip install -e ".\backend[dev]"

# 2. Node + Electron
npm install

# 3. Run the backend tests (sanity check)
cd backend
pytest
cd ..

# 4. Launch the app
npm run dev
```

On first launch the sidecar seeds the default rules and auto-detects your
Downloads, Documents and Pictures folders. Everything starts in
**preview mode** — nothing moves until you approve.

## Packaging (Windows installer)

```powershell
# Bundle the sidecar via PyInstaller (installs pyinstaller on demand)
pip install pyinstaller
pyinstaller --clean --onedir --name fileagent backend\fileagent\main.py -p backend
# Move the output so electron-builder can pick it up
Remove-Item -Recurse -Force backend\dist_sidecar -ErrorAction SilentlyContinue
Move-Item dist\fileagent backend\dist_sidecar

# Build + sign the installer
npm run package
# Output lives under release\FileAgent-<version>-Setup.exe
```

`electron-builder` is configured to include `backend/dist_sidecar/**` under
`resources/sidecar/`. The Electron main process resolves that path first when
looking for the sidecar binary and falls back to a dev venv when missing — so
the same code runs both packaged and from source.

## Modes of operation

| Mode          | What it does |
| ------------- | ------------ |
| **Analyze only** | Scan + classify + persist results. No proposals applied. |
| **Preview**      | Build a plan but never execute. Default for new rules. |
| **Approval**     | Build a plan; each action must be explicitly approved before apply. |
| **Semi-auto**    | Apply pre-approved actions; anything requiring approval stays pending. |
| **Auto (safe only)** | Apply only `safe` rules above their confidence threshold. |

Mode is selected globally (Settings tab) or per-rule (Rules tab). `sensitive`
rules always require approval regardless of the global mode.

## AI-assisted behavior

The `AIProvider` interface in `ai_provider.py` is deliberately minimal — it
only contributes a *topic hint* (invoice / contract / resume / identity /
manual) with a confidence score. The default is `NullProvider`, and the app is
fully functional without any model. When enabled, only filenames and short
excerpts (≤2KB) are sent to the provider. The UI clearly labels any AI-derived
suggestion as low-confidence until the user confirms.

## Scheduling

- The sidecar runs an in-process scheduler (`scheduler.Scheduler`) every 60 s
  that can fire `daily` / `weekly` / `startup` jobs from the `scheduled_jobs`
  table. No OS integration required.
- For OS-level scheduling, `scheduler.windows_task_command(exe_path)` emits a
  ready-to-copy `schtasks /Create ...` command. The installed binary supports a
  `--scheduled-run` flag that performs one plan+apply cycle and exits.

## Architectural decisions (for posterity)

- **Electron over Tauri / PySide6.** Tauri would be lighter but adds a Rust
  toolchain requirement and a more awkward Python sidecar story. PySide6 keeps
  everything in one language but makes multi-page dashboards significantly more
  work to polish. Electron + React is the pragmatic MVP choice.
- **Python sidecar over pure Node.** File classification, PDF/DOCX text
  extraction, and the future ML path are dramatically easier in Python. The
  loopback + bearer-token IPC model keeps the surface tiny.
- **SQLite over a richer ORM.** Raw `sqlite3` is enough; no migration framework
  required for MVP. Schema is idempotent and versioned in-place.
- **Rules-first classification.** Deterministic rules handle ~90% of real-world
  Downloads clutter cleanly. AI is explicitly optional; the UI never pretends
  a low-confidence AI hint is authoritative.
- **Every action is a row.** Both proposals and executions live in SQLite with
  full provenance. Rollback is a function of `executed_actions`, not an in-memory
  stack — surviving restarts trivially.
- **Safety is defense in depth.** The planner refuses to emit unsafe proposals,
  and the executor re-checks the same rules before each op. Rolling back also
  goes through safety.
